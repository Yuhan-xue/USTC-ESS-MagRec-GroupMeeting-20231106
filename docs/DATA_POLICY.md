# 数据边界

本仓库仅允许公开代码、文档、自绘结果图和明确列出的缩减统计。**原始数据绝不提交。**

## 原始数据与禁止内容

- 下载器产出的 `data/eq/f#####.npz`、`data/mer/f#####.npz`、`coords.npz`：即使只下载了二维切面，仍按原始输入处理。
- 同一切面的转换格式、完整场数组、逐帧导出及二维平均/探针中间缓存：不因“做过处理”就自动变成可提交的小数据。
- `frames/`、`output/cache/`、pickle、HDF5、NetCDF、VTK 等大型/原始场文件。
- 登录密码、token、cookie、浏览器配置、用户目录、教材/论文全文或截图拼图。

## 允许的小数据

仅 `processed/README.md` 所列的 8 个文件。NPZ 中每个数组必须是一维、数值类型、最多 1000 个元素，并匹配预先规定的键集合；单文件不超过 256 KiB，全部小数据不超过 1 MiB。CSV 限定为 90 行已提取的候选位置、喷流、电场及象限均值，不含任何二维场。

图像只允许精确列出的 PNG 自绘图，单张不超过 5 MiB。含第三方教材截图的 `cmp_*` 拼图以及 PPT 不允许入库。PNG 是对模拟的可视化结果，不是可逆的原始数值场。

## 三层防线

1. 在新建的干净目录中按白名单复制，**不在含原始数据的父目录初始化 Git**。
2. `.gitignore` 阻止常见输入、缓存、大型成品及凭据进入索引。
3. `tools/check_publication.py --staged` 直接读取 Git 暂存区的文件内容，而不是只看工作区；校验路径、大小、SHA-256、数据形状、JSON/CSV 结构、重联计数及常见凭据格式。

仓库发布后还需比对远端提交，并检查全部历史树路径，确保没有“先上传后删除”的原始数据。清单和检查器是防误操作措施，不构成对任意隐藏编码秘密的证明。
